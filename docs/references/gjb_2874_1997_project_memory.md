## 2. 这本标准管什么

标准针对带电传操纵系统的有人驾驶军用飞机，按任务、飞机类别、飞行阶段、使用/可用飞行包线以及正常/故障状态规定飞行品质。核心不是单一时域指标，而是以下约束的组合：

- 等级 1：飞行品质明显适合任务飞行阶段。
- 等级 2：仍可完成任务，但驾驶员工作负担增加或任务效果下降。
- 等级 3：仍可安全操纵，但工作负担过重或任务效果不好；A 类阶段应能安全终止。
- 定量分析、有人驾驶模拟、飞行试验和驾驶员评定共同构成一致性证据。复杂或非线性系统不能只凭一个低阶传递函数结论放行。
- 低阶等效系统（LOES）是把驾驶员实际感受到的总输入到总响应拟合成经典形式，再把标准中的模态、阻尼、频率和延迟边界应用到等效参数。它关注总响应，不要求把每一个高阶物理模态逐项解释出来。

因此，本项目最多能形成“按某一已声明建模与拟合方法得到的 GJB 启发式研究证据”。没有型号任务剪裁、全状态分析、有人在环/飞行试验和订购方认可时，不能称为正式 GJB 一致性结论。

## 4. 本项目实际控制对象

当前项目不是直接控制偏航角，也不是直接控制方向舵/副翼舵面。它研究的是 IV 类、A 种飞行阶段下的滚转速率通道：

```text
驾驶员滚转操纵力 F_pilot
          + RL 等效修正力 delta_F_RL
          = 等效输入 F_eq
                    |
                    v
         P-channel: F_as -> p
                    |
                    v
              滚转速率 p
```

`F_as` 是驾驶舱滚转操纵器的力输入。代码把 RL 输出作为同一输入点上的“等效研究修正力”，并不表示存在第二名驾驶员，也没有建立从力到真实舵偏、作动筒载荷或气动力矩的物理链路。

当前 P-channel 为

```math
\frac{p}{F_{as}} =
\frac{L_{F_a}s^2(s^2+2\zeta_\phi\omega_\phi s+\omega_\phi^2)}
{(s-\lambda_s)(s+1/T_R)(s^2+2\zeta_d\omega_d s+\omega_d^2)}
e^{-\tau_p s}.
```

项目 reference 保留原机的滚转模态、1 s 灵敏度和 `tau_p`，只令分子中的滚转-侧滑耦合零点与荷兰滚极点相消。SAC/Oracle 的任务是用受限的 `delta_F_RL` 让原始 P-channel 的 `p` 接近该诊断 reference。因此控制目标更准确地说是：

> 在有限等效输入权限内，减轻荷兰滚极点与滚转-侧滑零点失配对滚转速率响应的影响，同时不以饱和、抖动或伤害原本良好的飞机换取平均误差下降。

当前模型只输出 `p`，没有显式 `r`、`beta`、航向/侧滑状态或舵面状态，所以它不能证明完整横航向飞行品质已经得到控制。

## 5. GJB 中的滚转 LOES 与时间延迟

### 5.1 LOES 的定义边界

附录 A4.9（印刷 66-68，PDF 70-72）说明：高阶、非线性和增益系统会使真实响应偏离经典模型。承制方应找出最接近真实飞机总响应的等效经典系统，并与订购方确认拟合是否充分。经典传递函数通常还要加入时间延迟项，使先进系统的高频响应得到更合适的拟合；该延迟与驾驶员主观评价相关。

附录 A5.4.1.1.1（印刷 210-211，PDF 214-215）给出滚转速率对滚转操纵力的低阶等效形式，包含螺旋、滚转和荷兰滚模态以及指数延迟项，并要求在约 `0.1-10 rad/s` 内以等效系统拟合高阶系统。对 IV-A，表 A18 的等效滚转模态时间常数 `T_R` 建议上限为：等级 1 `1.0 s`，等级 2 `1.4 s`，等级 3 `10 s`。

附录 A5.4.1.1.5（印刷 246-247，PDF 250-251）把滚转轴等效时间延迟列为独立要求。原文说明该要求针对前置滤波器、SAS、舵机等的综合延迟作用；`tau_e` 要由滚转操纵输入到滚转速率响应的等效系统拟合确定。表 A21 的建议上限为：

| 飞行品质等级 | 滚转轴允许的等效时间延迟 |
| ---: | ---: |
| 1 | `0.10 s` |
| 2 | `0.20 s` |
| 3 | `0.25 s` |

这里的滚转轴下标在扫描件中排印为 `tau_e` 的滚转变量下标；本文统一简称 `tau_e`。它是拟合结果，不是一只硬件计时器。

### 5.2 为什么 `tau_e` 不是“采样周期决定的延迟”

假设把实际高阶闭环从指定输入到输出记为 `G_actual`，把选定 LOES 的有理部分记为 `G_LOES,rational`，则 `tau_e` 本质上来自未被有理部分解释的相位斜率：

```math
G_{actual}(j\omega) \approx
G_{LOES,rational}(j\omega;\vartheta)e^{-j\omega\tau_e}.
```

拟合会同时调整增益、极点、零点和 `tau_e`。因此 `tau_e` 依赖输入/输出定义、配平点、构形、拟合频带、权重和模型阶次，不等于任何单个部件的名义延迟，也不存在普遍精确的“各延迟直接相加”公式。

它可能吸收：

- 纯运输、通信、调度和计算延迟；
- 数字控制的采样与保持相位；
- 舵机/执行机构动态；
- 前置、传感器和结构滤波器；
- 增稳/控制增益系统及未显式保留的高阶模态；
- 拟合模型与真实响应之间剩余的相位差。

标准中的例子进一步说明 `tau_e` 不是字面死区：某些高阶响应甚至会拟合出负的等效延迟；这表示相对于所选低阶有理模型更“尖锐/超前”的响应，并不表示物理系统能预知未来。

### 5.3 采样、保持和执行机构各贡献什么

若“采样”指数字控制器的时间采样，理想零阶保持的频率响应为

```math
H_{ZOH}(j\omega)=e^{-j\omega T_s/2}
\frac{2\sin(\omega T_s/2)}{\omega T_s}.
```

在 Nyquist 频率以下且 sinc 项为正时，它表现出约 `T_s/2` 的相位延迟。项目的策略周期 `T_s=0.02 s`，所以仅零阶保持的低频等效贡献约为 `0.01 s`。真实数字链路还可能有 0 到多个采样周期的采集、计算和传输等待，但当前代码没有显式计算延迟。

若“采样”指从参数分布随机抽一架飞机，那么当前 `tau_p` 的数值确实由 Sobol 参数采样决定；这只是“随机抽到了多大的显式延迟”，并不表示这个延迟由 50 Hz 采样机制产生。两个“采样”含义不能混用。

一阶执行机构

```math
G_a(s)=\frac{1}{\tau_a s+1}
```

没有纯死区。`tau_a=0.08 s` 表示阶跃后约 `0.08 s` 到终值的 63.2%，约 `0.24 s` 到 95%。它在频率 `omega` 的相位是 `-atan(omega*tau_a)`；若只在该频点强行换算成纯延迟，则为

```math
tau_{a,phase}(\omega)=\frac{\arctan(\omega\tau_a)}{\omega},
```

这是随频率变化的量。LOES 又会同时重拟合其他参数，所以不能把 `0.08 s` 原样加到 `tau_p` 后就宣称得到标准的 `tau_e`。

GJB 的滚转讨论（印刷 224，PDF 228；印刷 287，PDF 291）也给出同样的工程含义：约 `3 rad/s` 的一阶前置滤波可减轻滚转锯齿，但会增加可观的总等效时间延迟；高增益飞机已有结构滤波、传感器滤波和数字时间延迟时，再加滤波器可能使总延迟不可接受。

## 7. 当前代码的端到端时序

每个 `RollQualityEnv.step()` 当前按以下顺序执行：

1. 在 50 Hz 时刻读取策略动作并裁剪。
2. 以 `4 s^-1` 对命令动作限速。
3. 用 `alpha = 1-exp(-0.02/0.08) = 0.221199...` 更新 RL 修正通道的一阶状态。
4. 形成 `F_eq = F_pilot + delta_F_RL`。
5. 把同一个 `F_eq` 保持四个 `0.005 s` P-channel 子步。
6. `PChannel` 在每个子步先经过按 `tau_p/0.005` 建立的分数 FIFO，再推进离散状态。
7. reference 同样以 200 Hz 推进，并保留相同的 `tau_p`，但它不经过 RL 的 `0.08 s` 一阶滤波。

当前没有独立的传感器延迟、策略推理耗时、通信延迟或一个完整控制周期的排队延迟。`0.08 s` 也不是由 `0.02 s` 推导出来的；它是此前人为选定的探索性修正通道常数。代码用连续一阶系统在 20 ms 端点上的精确系数更新状态，但随后把新值在本控制区间的四个 plant 子步内保持不变，因此它仍是 50 Hz 的离散近似，而不是 200 Hz 连续舵机模型。

## 8. 已确认的项目语义问题

### 8.1 `tau_p` 被误当作了 `tau_e`

命名、采样表和历史说明曾把 `tau_p` 称为等效滚转时延，但实现是明确的纯运输 FIFO。当前 3000 架 IV-A 机库还把 `tau_p` 扩展到约 `0.50 s`：

| split | 数量 | `tau_p` 最小值 | `tau_p` 最大值 |
| --- | ---: | ---: | ---: |
| train_core | 1200 | 0.000116 | 0.179866 |
| train_boundary | 600 | 0.080031 | 0.269952 |
| validation | 300 | 0.000270 | 0.179372 |
| id_test | 450 | 0.000148 | 0.179870 |
| ood_test | 300 | 0.250442 | 0.399679 |
| extreme_test | 150 | 0.400230 | 0.499665 |

这些可以作为运输延迟压力场景，但不能用表 A21 直接给 `tau_p` 打等级。尤其是 OOD/Extreme，有意超过表 A21 的等级 3 建议值，必须标为研究压力而不是“典型飞机”。

### 8.2 声称必需的 `delay_definition` 没有落到机库记录

采样配置要求保存 `delay_definition`，但当前 `plants.jsonl` 和 manifest 没有该字段。现有 3000 架飞机只能从代码反推其语义，数据本身不自描述。

### 8.3 `0.08 s actuator` 不是已辨识的物理舵机

它只过滤 `delta_F_RL`，而 `F_pilot` 不经过它；过滤后的量仍以牛顿表示并送入等效力输入点。更准确的名称应是“RL augmentation command lag”。除非先定义 RL 接入真实飞机的信号位置，并给出舵机/计算机/接口证据，否则不能把它称作真实飞机的作动筒模型。

若 `tau_p` 原本已经意图代表包含 SAS、滤波器和舵机在内的基线 `tau_e`，再把同一物理舵机解释进 `0.08 s` 会重复计入动态。若 `0.08 s` 是新增控制器接口动态，则应明确说明它不在基线 `tau_p` 内。当前文档尚未作出这个架构决定。

### 8.4 reference 的共同延迟会隐藏问题

raw 和 reference 保留同一个 `tau_p`，所以二者的 tracking RMSE 主要衡量极零失配，而不是考察运输延迟是否满足 GJB。这个 reference 适合作为“只消除耦合失配”的诊断目标，但不能用它证明最终系统的 `tau_e` 合格。

### 8.5 尚未实现 `tau_e` 的辨识

仓库目前没有在 `0.1-10 rad/s` 上联合拟合 `T_R`、荷兰滚参数、零点参数和 `tau_e` 的工具，也没有 LOES residual/拟合质量门槛。因此当前任何由 `tau_p` 推出的 GJB 延迟等级都不成立。

## 9. 后续统一做法

后续实现和实验必须遵循以下约定：

1. 保留旧字段兼容时，将 `tau_p` 的正式语义写为 `transport_delay_s`，不再称它为 `tau_e`。
2. 在 plant/run manifest 中分别记录 `plant_dt_s`、`control_period_s`、`transport_delay_s`、`computation_delay_s`、`augmentation_lag_time_constant_s`、保持方式、信号接入点和证据来源。
3. 明确 RL 修正是在驾驶员力、飞控指令还是舵面指令位置接入；只有这样才能判断基线动态是否被重复计算。
4. 对 raw、reference、受限 oracle 和每个最终策略，分别从同一声明的输入点到滚转速率 `p` 获取频响，并在 GJB 所述约 `0.1-10 rad/s` 范围联合拟合 LOES。
5. 保存拟合带宽、频率权重、参数约束、相位展开方法、`tau_e`、残差和可辨识性。残差不过门时不赋 GJB 延迟等级。
6. 对 50 Hz 控制器的端到端拟合必须包含实际采样、保持、推理/调度和修正通道动态；不能只读取 `tau_p`。
7. 小信号扫频/随机激励用于 LOES；饱和、限速、阶跃、双脉冲和扫频任务仍用于独立的非线性时域审计。二者不能互相替代。
8. 表 A21 只应用于最终拟合的滚转轴 `tau_e`，并同时报告 T_R、耦合、PIO、控制力/权限、故障状态和大气扰动证据。

在完成这些工作前，`tau_p`、`0.08 s` 和 `0.02 s` 都只能作为已声明的研究模型参数，不能单独支撑 GJB 等级结论。
